## Fixed run.cjs findArchive: pick the highest version, not the first listed

- **WHAT:** `hooks/run.cjs findArchive` now filters the matches, sorts them with `localeCompare(numeric: true)`, and returns the last one. New test `findArchive picks the highest version when several archives match` in `hooks/run.test.cjs` uses a fake `readdirSync` order (7.18.0 first, 10.0.0 in the middle, 8.0.0 last) so it fails on the old code, on a last-entry fix, and on a plain string sort. Plugin `CLAUDE.md` test command changed from `node --test hooks/` (fails on Node 24: "Cannot find module .../hooks") to `node --test hooks/*.test.cjs`.
- **WHY:** With the tracked 7.18.0 archives and the local 8.0.0 archive both in `bin/archives/`, `readdirSync` listed 7.18.0 first, so every Task 7 harness check ran the old binary.
- **HOW:** TDD. The first test version wrote real files and passed on the old code because this filesystem listed 10.0.0 first; replaced with an injected `fsImpl`. RED: actual `julie-v7.18.0`. GREEN: 21 tests pass (`node --test hooks/*.test.cjs`). Live check: `rm -rf bin/x86_64-unknown-linux-gnu`, one `node hooks/run.cjs --version` run extracted 8.0.0 (`.extracted-archive` = `julie-v8.0.0-...`).
- **IMPACT:** Task 7 harness checks can rerun against the right binary once the developer service runs 8.0.0.
