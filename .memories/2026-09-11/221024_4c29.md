## Plugin declares no MCP server for Codex and Antigravity

- **WHAT:** Deleted `mcp.json` (Agent Plugins MCP declaration) and `mcp_config.json` (Antigravity MCP declaration); removed `mcpServers` from `.codex-plugin/plugin.json`. README Codex and Antigravity sections now show the config entry (`[mcp_servers.julie]` in `~/.codex/config.toml`; `mcpServers.julie` in `~/.gemini/config/mcp_config.json`) with `node /absolute/path/to/julie-plugin/hooks/run.cjs`. CLAUDE.md tree and path-form sentence updated.
- **WHY:** Both harnesses start a plugin's MCP servers inside the plugin directory and send no MCP roots (probe plugin evidence in the julie finding `docs/findings/2026-09-11-deployment-story.md`). The plugin-declared server indexed the plugin directory and answered "No results". A config entry starts Julie in the project directory; verified with `codex exec` and `agy -p`, both returned `:52 find_default_sidecar_binary function`.
- **HOW:** Deletion, not a workaround. Claude Code keeps `.claude-plugin/plugin.json` `mcpServers` because Claude Code starts the plugin server in the project directory (verified: `plugin:julie:julie` connected and `mcp__plugin_julie_julie__fast_search` returned 6 hits).
- **IMPACT:** Codex and Antigravity installs are two steps: plugin (skills, hooks) plus one config block. `node --test hooks/*.test.cjs` 21 pass. Side finding: Antigravity ignores `hooks/hooks.json` (expects root `hooks.json`); no hook shipped for it.
