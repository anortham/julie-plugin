## WHAT

Completed and lead-reviewed the julie-plugin half of Plan 4B. The launcher now installs each selected archive into an immutable archive-named version directory, validates safe archive paths and the schema-2 package manifest, rejects symlinks and incomplete packages, promotes from a unique owned staging directory, and reuses only a matching ready version. Direct server/sidecar paths are accepted only as a paired symlink override to regular files.

## WHY

Overwriting a running Windows executable breaks upgrades, while partial or unsafe extraction can launch an incomplete or attacker-controlled package. Falling back to an older archive hides the actual failure and makes recovery unpredictable.

## HOW

Used Node standard library plus the existing system tar. Archive entries are listed and path-checked before extraction; staged output is checked for symlinks, manifest target/schema/file completeness, and the required sidecar before atomic rename. Errors preserve the actual cause and one recovery action. Lead review added traversal, symlink, malformed/incomplete, valid-old-version no-fallback, paired override, and ready-version reuse coverage.

## IMPACT

The plugin launcher no longer overwrites running versions or silently downgrades. The complete plugin Node gate passes 29/29. Native Windows lock qualification and real packaged-archive probes remain for Plan 4E/4D; no live install or publication occurred.
