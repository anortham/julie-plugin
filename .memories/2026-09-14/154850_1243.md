## WHAT

Fixed the pinned Julie plugin publication workflow in `.github/workflows/update-binaries.yml` and added focused contract coverage in `hooks/plugin-manifests.test.cjs`. Manual dispatch now falls back to the repository `github.token` for checkout and publish, while reusable calls still prefer the caller-supplied `publication_token`. Generated-snapshot validation now requires the two designed MCP files (`mcp.json` and `mcp_config.json`) and no longer requires nonexistent `mcp_codex.json`.

## WHY

The automatic Julie release job was skipped after a public-asset verifier false negative. A manual plugin dispatch then failed because workflow_dispatch had no caller secret. After temporarily supplying one, the workflow passed downloads, skill sync, manifests, and 30 hook tests but failed on `mcp_codex.json`, a filename absent from repository history and contradicted by the documented one-manifest-per-harness design.

## HOW

Worked from reviewed source commit `7d3996a7...` in an isolated worktree. A Luna worker added focused assertions first and observed the exact test fail, then made the minimal workflow changes and observed the same test pass. The hosted Linux workflow already proved the unchanged 30-test baseline green before hitting the bad file assertion. The temporary repository secret was removed immediately after diagnosis.

## IMPACT

A new immutable plugin source commit/tag can be safely dispatched without temporary secrets, and future reusable Julie release calls keep cross-repo authentication. This unblocks publishing the v8.0.0 plugin snapshot from the already-valid public Julie release.
